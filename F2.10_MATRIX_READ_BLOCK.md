# F2.10 — Extracción por bloque de lecturas Matrix

## Cambio de estrategia

F2.10 ya no mueve un endpoint aislado. Extrae en conjunto cuatro lecturas
legacy que pertenecen al mismo contexto funcional de administración Matrix:

- GET `/api/matriz/frentes`
- GET `/api/matriz/atributos`
- GET `/api/matriz/sub-motivos`
- GET `/api/reglas-evaluacion`

Estas se suman a las seis lecturas que MatrixModule ya absorbió en F2.9.

## Resultado

MatrixModule pasa a manejar 10 lecturas productivas.

```text
server.js
   ↓
MatrixRoutes
   ↓
MatrixController
   ↓
MatrixService
   ↓
MatrixRepository
```

## Contratos preservados

### Frentes
HTTP 200 + array.
Error -> 500 `{error: mensaje}`.

### Atributos
`?frente_id=` continúa siendo opcional.
Sin filtro ordena por `frente_id, orden`.

### Submotivos
`?atributo_id=` continúa siendo opcional.
Sin filtro ordena por `atributo_id, orden`.

### Reglas administrativas
HTTP 200 + array.
El comportamiento histórico extraño ante fallo también se conserva:
HTTP 500 + `[]`.

## Qué NO se toca

F2.10 no mueve escrituras:

- POST/PUT/DELETE frentes
- POST/DELETE atributos
- POST/DELETE submotivos
- congelar/crear/activar versiones
- recalcular
- validadores de pesos
- CRUD de escritura de reglas

Eso corresponde a F2.11, donde necesitaremos transacciones y una
caracterización más estricta.

## Pruebas

```powershell
npm test
```

Luego validar manualmente:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/matriz/frentes', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log('FRENTES', r.status, await r.json()));

fetch('/api/matriz/atributos?frente_id=1', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log('ATRIBUTOS', r.status, await r.json()));

fetch('/api/matriz/sub-motivos?atributo_id=1', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log('SUBMOTIVOS', r.status, await r.json()));

fetch('/api/reglas-evaluacion', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log('REGLAS', r.status, await r.json()));
```

Además comprobar Supervisor > Administrador de Matriz y Auditor.

- npm test = 0 fail
- cuatro endpoints devuelven lo mismo que antes
- filtros opcionales funcionan
- Administrador de Matriz carga normalmente
