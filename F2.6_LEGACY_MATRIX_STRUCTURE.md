# F2.6 — Estructura completa de matriz fuera de server.js

## Endpoint migrado

`GET /api/matriz/versiones/:id/estructura`

Este endpoint es usado por el Administrador de Matriz del Supervisor.

## Antes

`server.js` hacía:

1. SELECT de `versiones_matriz`
2. SELECT de `version_frentes`
3. por cada frente, SELECT de `version_atributos`
4. por cada atributo, SELECT de `version_sub_motivos`
5. armado del JSON jerárquico

## Después

```text
server.js
    ↓
LegacyMatrixService.getStructure()
    ↓
LegacyMatrixRepository.getLegacyMatrixStructure()
    ↓
PostgreSQL
```

`server.js` queda responsable únicamente de HTTP.

## Contrato preservado

Respuesta 200:

```text
{
  version: {...},
  frentes: [
    {
      ...frente,
      atributos: [
        {
          ...atributo,
          sub_motivos: [...]
        }
      ]
    }
  ]
}
```

También se conservan:

- 401 sin token
- 400 ID inválido
- 404 versión inexistente
- 500 error inesperado

## Nota técnica

F2.6 conserva deliberadamente el patrón N+1 del endpoint actual para garantizar equivalencia funcional.

NO optimizamos todavía las consultas en esta fase.

Después de estabilizar el módulo podremos sustituirlo por una consulta agregada/JSON o un conjunto reducido de queries y medir rendimiento, pero mezclar optimización con refactorización elevaría el riesgo.

## Pruebas

Luego:

Prueba directa:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/matriz/versiones/1/estructura', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

## Criterio de aceptación

- 0 fail
- 200 en versión válida
- estructura visual idéntica
- sin regresiones F2.3/F2.4/F2.5
- registro/edición de evaluación funcionando
