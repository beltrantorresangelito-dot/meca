# F1.8 — Matriz → Quiebre

## Decisión de dominio

Una Matriz pertenece a un Quiebre, no a una Campaña.

La relación conceptual queda:

```text
QUIEBRE
   1
   |
   N
MATRIZ
   1
   |
   N
VERSION_MATRIZ
```

Las campañas se asociarán a matrices mediante una relación independiente, porque:

- varias campañas pueden compartir una misma matriz;
- una campaña podría cambiar de matriz con el tiempo;
- no debemos duplicar una matriz por campaña.

## Qué crea F1.8

### `matrices`

Campos principales:

- `id`
- `quiebre_id`
- `codigo`
- `nombre`
- `descripcion`
- `activa`
- timestamps

La combinación `(quiebre_id, codigo)` es única.

### `versiones_matriz.matriz_id`

Todas las versiones históricas existentes se migran a:

`MATRIZ_COBRANZAS`

perteneciente al Quiebre:

`COBRANZAS`

## Qué NO cambia

F1.8 no modifica:

- `campanas`
- `evaluaciones`
- `detalles_evaluacion`
- `reglas_evaluacion`
- Auditor
- Supervisor
- server.js
- Python/ML

Las evaluaciones históricas continúan apuntando exactamente a los mismos `versiones_matriz.id`.

## Verificación PostgreSQL

### Matrices creadas

```sql
SELECT
    m.id,
    m.codigo,
    m.nombre,
    q.codigo AS quiebre,
    m.activa
FROM matrices m
JOIN quiebres q ON q.id = m.quiebre_id
ORDER BY m.id;
```

Debe existir:

`MATRIZ_COBRANZAS | Cobranzas`

### Versiones asociadas

```sql
SELECT
    vm.id,
    vm.version,
    vm.fecha_vigencia,
    m.codigo AS matriz,
    q.codigo AS quiebre
FROM versiones_matriz vm
JOIN matrices m ON m.id = vm.matriz_id
JOIN quiebres q ON q.id = m.quiebre_id
ORDER BY vm.id;
```

Todas las versiones actuales deben quedar bajo `MATRIZ_COBRANZAS / COBRANZAS`.

### Huérfanas

```sql
SELECT COUNT(*) AS versiones_sin_matriz
FROM versiones_matriz
WHERE matriz_id IS NULL;
```

Debe devolver `0`.

## Reversibilidad

Antes de introducir la relación Campaña ↔ Matriz, probar:

```powershell

npm run db:status
npm run db:migrate
npm run db:status
```

## Validación funcional

Después de reaplicar:

- iniciar MECA;
- abrir editor/gestión de matriz;
- cargar versión activa;
- registrar evaluación;
- editar evaluación;
- consultar histórico;
- comprobar reportes que usan versión de matriz.

Todo debe funcionar igual.

## Próximo paso

Después de F1.8, el modelo permite crear una relación flexible:

```text
CAMPAÑA N:M MATRIZ
```

preferiblemente con vigencias, para que:

- Campaña A y B compartan Matriz X;
- Campaña C use Matriz Y;
- una campaña pueda cambiar de matriz sin perder historial.

No se implementa esa relación dentro de F1.8 para mantener esta migración pequeña y reversible.
