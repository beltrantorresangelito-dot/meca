# F1.9 — Campaña ↔ Matriz con vigencia

## Modelo

```text
QUIEBRE
├── CAMPAÑAS
└── MATRICES
      └── VERSIONES

CAMPAÑA N:M MATRIZ
     mediante
campana_matriz
```

La relación N:M es deliberada:

- varias campañas pueden compartir una misma matriz;
- una campaña puede cambiar de matriz a lo largo del tiempo;
- no se duplica una matriz por campaña;
- las evaluaciones históricas siguen conservando `version_matriz_id`.

## Regla de selección

Para una llamada/evaluación en una fecha determinada, la futura lógica de aplicación deberá resolver la asociación cuya vigencia contenga esa fecha:

```sql
vigente_desde <= fecha_objetivo
AND (vigente_hasta IS NULL OR vigente_hasta >= fecha_objetivo)
AND activa = TRUE
```

La selección automática en Node se implementará después de completar la capa de dominio/API. F1.9 solo construye y protege el modelo de datos.

## Protecciones

### Mismo Quiebre

El trigger `validar_campana_matriz` impide asociar, por ejemplo:

- Campaña de COBRANZAS
- con una Matriz de FRAUDE

### No solapamiento

Una campaña no puede tener dos matrices activas cuyos periodos se superpongan.

Ejemplo permitido:

```text
Campaña A
Matriz X: 1900-01-01 → 2026-12-31
Matriz Y: 2027-01-01 → abierto
```

Ejemplo rechazado:

```text
Matriz X: 2026-01-01 → abierto
Matriz Y: 2026-06-01 → abierto
```

## Migración inicial

Todas las campañas existentes quedan relacionadas con:

`MATRIZ_COBRANZAS`

desde:

`1900-01-01`

hasta vigencia abierta.

Se usa esa fecha deliberadamente para que no aparezca un corte artificial entre datos históricos y el nuevo modelo. Las evaluaciones históricas continúan resolviéndose por su `version_matriz_id`.

## Verificación

```sql
SELECT
    c.codigo AS campana,
    q.codigo AS quiebre,
    m.codigo AS matriz,
    cm.vigente_desde,
    cm.vigente_hasta,
    cm.activa
FROM campana_matriz cm
JOIN campanas c ON c.id = cm.campana_id
JOIN matrices m ON m.id = cm.matriz_id
JOIN quiebres q ON q.id = c.quiebre_id
ORDER BY c.id, cm.vigente_desde;
```

Todas las campañas actuales deben apuntar a `MATRIZ_COBRANZAS`.

Campañas sin asociación activa:

```sql
SELECT c.id, c.codigo
FROM campanas c
WHERE NOT EXISTS (
    SELECT 1
    FROM campana_matriz cm
    WHERE cm.campana_id = c.id
      AND cm.activa = TRUE
);
```

Debe devolver cero filas.

Validación cruzada de Quiebre:

```sql
SELECT
    c.codigo AS campana,
    qc.codigo AS quiebre_campana,
    m.codigo AS matriz,
    qm.codigo AS quiebre_matriz
FROM campana_matriz cm
JOIN campanas c ON c.id = cm.campana_id
JOIN quiebres qc ON qc.id = c.quiebre_id
JOIN matrices m ON m.id = cm.matriz_id
JOIN quiebres qm ON qm.id = m.quiebre_id
WHERE qc.id <> qm.id;
```

Debe devolver cero filas.

## Rollback

Antes de que otra migración dependa de esta tabla:

```powershell
npm run db:rollback
npm run db:status
npm run db:migrate
npm run db:status
```

- matriz debe seguir funcionando;
- creación/edición de evaluación debe seguir funcionando;
- reportes deben seguir funcionando;
- Audio/IA no cambia.
