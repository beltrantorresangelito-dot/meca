# F3.2 — ReportsRepository

## Objetivo

Extraer las consultas SQL del bloque Reportes sin mover todavía los handlers
HTTP ni cambiar contratos.

## Nuevo componente

`src/modules/reports/reports.repository.js`

Responsabilidades:
- consultas de evaluaciones;
- fechas disponibles;
- detalles fallidos;
- errores por auditor;
- nombres de auditores;
- detalles por evaluación;
- líderes;
- resúmenes por líder, ubicación y localidad.

## Decisión deliberada

`/api/reportes/evaluaciones-con-detalles` conserva el patrón N+1:

1. consulta evaluaciones;
2. por cada evaluación consulta sus detalles.

No se optimiza todavía. F3.2 separa responsabilidades; una optimización futura
podrá cambiarlo con tests de equivalencia.

## Qué cambia en server.js

Los handlers siguen existiendo exactamente en el mismo lugar y siguen
construyendo las mismas respuestas, pero ya no ejecutan SQL directamente:

```text
server.js handler
   ↓
ReportsRepository
   ↓
PostgreSQL
```

## Qué NO cambia

- URLs;
- códigos HTTP;
- autorización;
- formatos JSON;
- lógica de normalización de fechas;
- agregación de errores por auditor;
- mapeo camelCase de resúmenes.

## Pruebas

```powershell
npm test
```

Esperado:
`0 fail`.

Después de quedar verde, F3.3 moverá transformación y lógica de Reportes a
`ReportsService`, manteniendo todavía las rutas inline.
