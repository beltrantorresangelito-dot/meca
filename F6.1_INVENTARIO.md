## Dependencias críticas detectadas

- `pool` / PostgreSQL: usuarios, roles, rol_pestanas y pestanas_sistema.
- `hashPassword` y `verifyPassword`: alta/cambio/login.
- `signToken` y `verifyToken`: acceso y token temporal `password_change`.
- `authorizeRequest`: autorización central antes de los handlers inline.
- Compatibilidad de login con `rol_id`, `rol_codigo`, `rol_nombre` y campo `rol` en la respuesta.

## Estrategia propuesta para F6

1. F6.1 — caracterización (este paquete).
2. F6.2 — Repository de Usuarios/Auth sin cambiar rutas.
3. F6.3 — Service de Usuarios/Auth.
4. F6.4 — Controller + Routes y retiro de handlers inline de usuarios/auth.
5. F6.5 — Roles/Permisos como subdominio separado para reducir riesgo.
6. F6.6 — validación funcional + checkpoint Git.

### Decisión importante
No conviene mover Usuarios + Roles + Permisos + Auth de una sola vez. Auth y usuarios comparten credenciales, pero roles/pestañas tienen reglas administrativas propias. Se separarán progresivamente manteniendo los contratos HTTP existentes.
