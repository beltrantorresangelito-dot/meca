# F5.2 — Caracterización de Escuchas

## Objetivo

Congelar el comportamiento actual del dominio Escuchas antes de mover SQL o
crear un módulo dedicado.

**F5.2 no modifica código productivo.**

## Endpoints/condiciones detectados en `server.js`

- `ruta === '/api/escuchas/asignaciones' && metodo === 'POST'`
- `ruta === '/api/escuchas/asignaciones' && metodo === 'GET'`
- `ruta === '/api/escuchas/tareas' && metodo === 'GET'`
- `ruta === '/api/escuchas/tareas' && metodo === 'POST'`
- `ruta === '/api/escuchas/mis-escuchas' && metodo === 'GET'`
- `ruta === '/api/escuchas/reactivar' && metodo === 'PUT'`

## Contratos que se congelan

### Asignaciones
- POST requiere `tarea_id` y array no vacío.
- Detecta duplicados por `ticket + tarea_id`.
- Reporta `insertados` y `duplicados`.
- GET devuelve `[]` en ciertos errores legacy.

### Tareas / lotes
- GET ordena por id descendente.
- POST valida `id` y `fecha_carga`.
- Previene duplicados por `nombre_archivo` en ventana de 5 minutos.
- Si detecta duplicado, reutiliza el lote.
- DELETE usa transacción y elimina asignaciones relacionadas.

### Flujo de escucha
- mis-escuchas filtra por auditor.
- solo audio_disponible=true.
- estados pendientes/en_proceso.
- iniciar -> `en_proceso`.
- gestionar -> `gestionado` + `fecha_gestion`.
- cancelar -> `pendiente`.
- incidencia -> audio no disponible + motivo + fecha.
- reactivar por ticket -> `pendiente`.

## Exclusión

No forma parte de F5.2:
- `/api/audio/reproducir/:ticketId`
- `/api/audio/verificar/:ticketId`

Esos endpoints pertenecen al futuro módulo AudioProxy.
