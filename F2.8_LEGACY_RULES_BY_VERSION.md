# F2.8 — Reglas de evaluación por versión fuera de server.js

Se migra únicamente:

`GET /api/reglas-evaluacion/version/:id`

## Comportamiento legacy preservado

Este endpoint es deliberadamente tolerante:

- tabla `reglas_evaluacion` inexistente -> HTTP 200 + `[]`
- consulta válida sin reglas -> HTTP 200 + `[]`
- reglas existentes -> HTTP 200 + array
- error interno -> HTTP 200 + `[]`
- sin token -> HTTP 401

Este comportamiento se conserva para no bloquear el formulario de evaluación
por un fallo de reglas opcionales.

## Arquitectura

```text
server.js
   ↓
LegacyMatrixService.getEvaluationRulesByVersion()
   ↓
LegacyMatrixRepository.getLegacyEvaluationRulesByVersion()
   ↓
PostgreSQL
```

## Qué NO se migra

El CRUD administrativo permanece en server.js:

- GET /api/reglas-evaluacion
- POST /api/reglas-evaluacion
- PUT ...
- DELETE ...

F2.8 es solo lectura.

## Pruebas

```powershell
npm test
```

Prueba manual:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/reglas-evaluacion/version/4', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

Esperado: HTTP 200 y array.

Después validar una evaluación en el Auditor para comprobar que las reglas NA
y demás comportamientos condicionados siguen cargando igual.

## Criterio de aceptación

- 0 fail
- endpoint 200
- reglas cargan igual
- evaluación funciona
- NA sigue comportándose igual
- CRUD administrativo sin regresiones
