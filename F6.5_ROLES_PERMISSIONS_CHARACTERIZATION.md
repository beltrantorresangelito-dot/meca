# F6.5 — Caracterización de Roles y Permisos

## Objetivo

Congelar el comportamiento actual antes de modularizar Roles/Permisos.
**Esta fase no modifica producción.**

## Endpoints caracterizados

| Método | Ruta | Área |
|---|---|---|
| GET | `/api/auth/redirect` | Roles/Auth |
| PUT | `/api/roles/:id/redirect` | Roles |
| GET | `/api/pestanas/todas` | Permisos |
| GET | `/api/rol-pestanas/:rolId` | Permisos |
| GET | `/api/roles` | Roles |
| PUT | `/api/roles/:id` | Roles/Permisos |
| POST | `/api/roles` | Roles |
| PUT | `/api/roles/:id/desactivar` | Roles |
| PUT | `/api/roles/:id/reactivar` | Roles |
| DELETE | `/api/roles/:id` | Roles |
| DELETE | `/api/rol-pestanas/:rolId` | Permisos |
| GET | `/api/pestanas` | Permisos |

## Contratos congelados

- redirect por rol con fallback AUDITOR/SUPERVISOR;
- redirect_url debe existir y comenzar con `/`;
- GET roles incluye redirect_url;
- creación de rol rechaza código duplicado;
- update de rol valida existencia y código duplicado;
- update de rol puede reemplazar rol_pestanas;
- desactivar/reactivar conserva mensajes y estados;
- reactivar detecta rol ya activo;
- delete conserva 404 si rol no existe;
- pestañas admin devuelve todas;
- rol-pestanas GET/DELETE conserva relación;
- pestañas visibles conserva orden.
