# F1.4-B — Autorización administrativa

## Objetivo
Diferenciar autenticación (quién es el usuario) de autorización (qué puede hacer).

## Alcance compatible
Esta etapa protege operaciones administrativas sensibles sin alterar los flujos operativos del Auditor.

### Bloqueado para rol AUDITOR
- Administración general de usuarios (`/api/usuarios` y `/api/usuarios/:id`).
- Exportación/gestión administrativa de usuarios.
- Administración de roles.
- Administración de asignación rol-pestaña.
- Consulta administrativa de todas las pestañas.
- Cambio de redirect de roles.

### Se mantiene para Auditor
- Consulta de auditores/auditores activos usada por flujos existentes.
- Evaluaciones.
- Escuchas.
- Audio/transcripción.
- Rutas no clasificadas todavía como administrativas.

## Estrategia temporal
El sistema legacy trata los roles distintos de AUDITOR como perfiles de Supervisor/administración. Para no romper roles configurables existentes, F1.4-B conserva ese comportamiento.

Esto NO es el modelo final. Más adelante se migrará a permisos funcionales (`evaluation.read`, `users.manage`, etc.) y alcance por Quiebre.

## Validación
Ejecutar:

    npm test

Y manualmente:
1. Supervisor: Gestión de usuarios abre y permite operaciones normales.
2. Supervisor: Gestión de roles/pestañas funciona.
3. Auditor: formulario, escuchas y evaluación continúan funcionando.
4. Un Auditor no debe poder invocar manualmente una operación administrativa protegida aunque tenga un token válido.
