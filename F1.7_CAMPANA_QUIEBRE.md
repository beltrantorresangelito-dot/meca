# F1.7 — Campaña → Quiebre

## Objetivo

Formalizar la relación:

`Quiebre 1:N Campaña`

sin modificar todavía las relaciones existentes de `evaluaciones` y `asignaciones_escucha` con `campanas`.

## Migración

`0003_campanas_quiebre`

Hace lo siguiente:

1. Agrega `campanas.quiebre_id`.
2. Busca el quiebre `COBRANZAS`.
3. Asigna todas las campañas existentes a `COBRANZAS`.
4. Verifica que no quede ninguna campaña con `quiebre_id IS NULL`.
5. Convierte `quiebre_id` en `NOT NULL`.
6. Crea FK a `quiebres(id)` con `ON DELETE RESTRICT`.
7. Crea índice por `quiebre_id`.

## Razón de ON DELETE RESTRICT

No queremos que eliminar accidentalmente un Quiebre elimine sus campañas. Si un Quiebre tiene campañas asociadas, PostgreSQL debe impedir su eliminación física.

## Qué NO cambia

- `evaluaciones.campana_id`
- `asignaciones_escucha.campana_id`
- frontend
- `server.js`
- Python/ML
- matriz

Las entidades existentes continúan apuntando a `campanas`, por lo que el funcionamiento actual permanece compatible.

## Ejecución

```powershell
npm test

npm run db:status
```

## Verificación PostgreSQL

```sql
SELECT
    c.id,
    c.codigo,
    c.descripcion,
    q.codigo AS quiebre_codigo,
    q.nombre AS quiebre_nombre
FROM campanas c
JOIN quiebres q ON q.id = c.quiebre_id
ORDER BY c.id;
```

Todas las campañas actuales deben mostrar `COBRANZAS`.

Comprobar huérfanas:

```sql
SELECT COUNT(*) AS campanas_sin_quiebre
FROM campanas
WHERE quiebre_id IS NULL;
```

Debe devolver `0`.

## Reversibilidad

Antes de F1.8 puedes probar:

```powershell
npm run db:rollback
npm run db:status
npm run db:migrate
npm run db:status
```

El rollback elimina solamente `campanas.quiebre_id`, su índice y su FK.

## Validación funcional

Después de reaplicar:

- Iniciar MECA.
- Supervisor: consultar campañas.
- Crear/editar campaña si esa función está habilitada.
- Auditor: cargar una escucha con campaña.
- Registrar/editar una evaluación.
- Confirmar que reportes por campaña siguen funcionando.

## Criterio de aceptación

F1.7 se considera cerrada cuando:

- Suite: 0 fail.
- 0003 aplicada.
- 0 campañas sin Quiebre.
- Todas las campañas históricas pertenecen a COBRANZAS.
- Rollback/reaplicación funciona antes de avanzar.
- MECA funciona sin regresiones.
