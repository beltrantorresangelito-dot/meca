# F2.5 — Versión legacy por fecha

Se migra:

`GET /api/matriz/versiones/por-fecha?fecha=YYYY-MM-DD`

## Contrato preservado

- Sin token: 401.
- Sin `fecha`: 400 `{error:"Fecha requerida"}`.
- Sin versión aplicable: 404 `{error:"No hay versión para esta fecha"}`.
- Con versión: 200 + objeto completo `versiones_matriz`.
- Error: 500.

## Arquitectura

Antes:

`server.js -> pool.query`

Después:

`server.js -> LegacyMatrixService -> LegacyMatrixRepository -> PostgreSQL`

## Nota de arquitectura

Este endpoint sigue siendo **legacy** porque selecciona una versión global solo por fecha.

El modelo definitivo de MECA Platform ya permite:

`Campaña + Fecha -> Matriz -> Versión`

No cambiaremos el contrato actual hasta migrar el frontend consumidor.

## Pruebas

```powershell
npm test
```

En consola:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/matriz/versiones/por-fecha?fecha=2026-08-22', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

Debe devolver 200 para una fecha con versión aplicable.

También probar sin fecha:

```javascript
fetch('/api/matriz/versiones/por-fecha', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

Debe devolver 400.
