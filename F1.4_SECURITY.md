# F1.4 — Seguridad P0 (tramo compatible)

## Cambios implementados

1. **Contraseñas**
   - Nuevas contraseñas se almacenan con `scrypt` usando `crypto` nativo de Node.js.
   - Contraseñas SHA-256 existentes siguen autenticando.
   - Tras un login exitoso con SHA-256, el hash se migra automáticamente a scrypt sin pedir cambio al usuario.

2. **Tokens**
   - Se reemplaza la firma fija `firma-simple` por HMAC-SHA256 real usando `AUTH_SECRET`.
   - Un token alterado es rechazado.
   - Los tokens tienen propósito (`access` o `password_change`).
   - El token de primer cambio de contraseña dura 10 minutos y no sirve para consumir el resto de APIs.

3. **Primer login**
   - El cambio de contraseña ya no acepta solo `usuarioId`.
   - Requiere un token temporal generado después de validar correctamente las credenciales originales.

4. **Validación central de Bearer tokens**
   - Cualquier Bearer token recibido por `server.js` se valida criptográficamente antes de continuar.
   - Esto refuerza los endpoints legacy que hoy solo verifican la presencia del header.

5. **CORS**
   - Se elimina `Access-Control-Allow-Origin: *` del servidor principal.
   - Los orígenes cross-origin permitidos se configuran en `CORS_ORIGINS`.
   - Si frontend y backend usan el mismo origen, no es necesario agregar CORS.

6. **PostgreSQL**
   - Se elimina el password fallback hardcodeado de `models/database.js`.
   - Se utiliza `DATABASE_URL` si existe; alternativamente se requieren `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` y `DB_NAME`.
   - `scripts/init-db.js` también deja de tener credenciales hardcodeadas.

## Configuración requerida

Agregar a `.env` (NO versionar el valor real):

```env
AUTH_SECRET=<secreto aleatorio de al menos 32 caracteres>
```

Generar uno en PowerShell usando Node:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Si existe una llamada cross-origin real al backend:

```env
CORS_ORIGINS=http://localhost:8080,http://otra-url-permitida
```

## Compatibilidad

- No requiere instalar paquetes npm adicionales.
- Los usuarios existentes no necesitan cambiar su contraseña: se migra automáticamente al autenticarse.
- Las sesiones/token antiguos dejarán de ser válidos después de desplegar este cambio. El usuario deberá iniciar sesión nuevamente una vez.

## Pendiente dentro de Seguridad

- Autorización granular por permiso + Quiebre. F1.4 valida identidad/token, pero no cambia todavía el modelo `rol -> pestaña`.
- Retirar secretos existentes dentro de PostgreSQL (`conexion_remota`, passwords de tareas) se hará mediante migración controlada al entrar a F1.5, para no eliminar datos/configuración sin conocer su uso operacional.
