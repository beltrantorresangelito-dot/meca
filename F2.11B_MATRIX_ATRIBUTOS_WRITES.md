# F2.11-B — Escrituras Matrix: Atributos

Se migran al MatrixModule:

- POST `/api/matriz/atributos`
- PUT `/api/matriz/atributos/:id`
- DELETE `/api/matriz/atributos/:id`

## Hallazgos

### 1. DELETE estaba desalineado con la BD
El servidor legacy todavía intentaba borrar de:
- atributos
- sub_motivos

Ahora usa:
- version_atributos
- version_sub_motivos
- version_frentes para verificar pertenencia a la versión activa.

### 2. El frontend usa UPDATE pero server.js no tenía PUT inline
Supervisor llama `API.actualizarAtributo(id, data)` cuando se edita un atributo.

F2.11-B implementa formalmente:
`PUT /api/matriz/atributos/:id`

sobre la estructura versionada.

## Reglas

Crear/editar:
- exige versión activa;
- el frente debe pertenecer a esa versión;
- peso > 0;
- nombre no duplicado dentro del mismo frente/version;
- suma de atributos no puede superar peso_maximo del frente.

Eliminar:
- solo atributo de la versión activa;
- elimina submotivos versionados primero;
- luego atributo;
- todo en transacción;
- conserva mensaje con cantidad de submotivos eliminados.

## Pruebas funcionales

Después de `npm test`:

1. En Supervisor, edita un atributo existente cambiando temporalmente solo el nombre.
2. Guarda y verifica que recarga correctamente.
3. Restaura el nombre.
4. Para CREATE, usa un peso que no haga superar el peso del frente.
5. DELETE solo sobre un atributo temporal/de prueba.

Los IDs actuales conocidos de ENC incluyen, por ejemplo, atributo 43.
No elimines un atributo productivo solo para probar.
