# F1.10 Fix — Tipos de retorno

La migración 0006 creó correctamente la lógica de resolución, pero PostgreSQL detectó una diferencia entre el contrato `BIGINT` de la función y columnas físicas como `campanas.id`, que actualmente son `INTEGER`.

No se modifica 0006 porque ya fue aplicada y su checksum debe permanecer inmutable.

0007 reemplaza la función usando casts explícitos:

- IDs -> BIGINT
- códigos/version -> VARCHAR
- fecha_vigencia -> DATE

## Aplicar

```powershell
npm test
npm run db:status
npm run db:migrate
npm run db:status
```

Después:

```sql
SELECT *
FROM resolver_contexto_evaluacion(1, CURRENT_DATE);
```

y:

```sql
SELECT *
FROM resolver_contexto_evaluacion(1, DATE '2025-01-01');
```

La primera debe devolver exactamente una fila si existe una versión vigente.
