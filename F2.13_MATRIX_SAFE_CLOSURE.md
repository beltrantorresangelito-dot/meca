# F2.13 — Cierre seguro de Matrix

## Radiografía previa

Después de F2.12, `server.js` todavía contenía tres zonas relacionadas
directamente con Matriz:

1. `/api/evaluacion/estructura`
2. CRUD de `/api/reglas-evaluacion`
3. `/api/matriz/recalcular`

Los dos primeros son operaciones normales y seguras de modularizar.

El tercero modifica evaluaciones históricas y queda deliberadamente fuera.

## Se mueve a MatrixModule

### Lectura
- GET `/api/evaluacion/estructura`

### Escrituras
- POST `/api/reglas-evaluacion`
- PUT `/api/reglas-evaluacion/:id`
- DELETE `/api/reglas-evaluacion/:id`

## Corrección de /api/evaluacion/estructura

El handler antiguo consultaba:
- `frentes`
- `atributos`
- `sub_motivos`

Esas tablas ya no representan la matriz vigente.

F2.13 reutiliza el árbol versionado:
- `version_frentes`
- `version_atributos`
- `version_sub_motivos`

y las reglas de la versión activa.

Se conserva el contrato:

```json
{
  "version": "v2.1.0",
  "frentes": [],
  "reglas": []
}
```

## Reglas

El CRUD conserva:
- 201 en creación;
- 200 en actualización;
- 404 si la regla no existe;
- 200 + success al eliminar;
- JSONB correcto para `submotivos_afectados` y `excepciones`.

## Lo único Matrix que queda en server.js

`POST /api/matriz/recalcular`

No debe moverse ni ejecutarse todavía.

Ese endpoint:
- lee la tabla legacy `sub_motivos`;
- sobrescribe pesos en `detalles_evaluacion`;
- recalcula `evaluaciones`.

Por tanto, se tratará como migración/reprocesamiento histórico, no como
operación administrativa normal.

## Validación

1. `npm test`
2. Supervisor > Reglas de Evaluación:
   - crear regla temporal;
   - editar;
   - eliminar.
3. Consola:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/evaluacion/estructura', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

Debe responder 200 y mostrar la versión activa con estructura versionada.
