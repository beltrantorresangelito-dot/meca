# F2.12 — Ciclo de vida de versiones de Matriz

## Se extrae a MatrixModule

- POST `/api/matriz/versiones/congelar`
- POST `/api/matriz/versiones` (compatibilidad legacy)
- PUT `/api/matriz/versiones/:id/activar`
- POST `/api/matriz/validar/frentes`
- POST `/api/matriz/validar/atributos`
- POST `/api/matriz/validar/sub-motivos`

Se agrega además:

- GET `/api/matriz/versiones/:id/integridad`

## Correcciones estructurales

### 1. matriz_id

El snapshot ahora hereda `matriz_id` de la versión activa.

### 2. Snapshot semántico completo

Además de frentes, atributos y submotivos, se preservan:
- `clasificacion` de submotivos;
- reglas de evaluación, si existe la tabla `reglas_evaluacion`.

### 3. Activación transaccional

La activación:
1. verifica que exista la versión;
2. verifica integridad de pesos;
3. desactiva la versión actual;
4. activa la elegida;
5. hace COMMIT.

Cualquier error produce ROLLBACK.

### 4. Validadores versionados

Los tres validadores dejan de consultar:
- frentes
- atributos
- sub_motivos

y usan:
- version_frentes
- version_atributos
- version_sub_motivos

## Integridad exigida para activar

- frentes = 100%;
- atributos de cada frente = peso del frente;
- submotivos de cada atributo = peso del atributo.

## Decisión deliberada: recalcular históricos NO se migra

`POST /api/matriz/recalcular` queda temporalmente en `server.js`.

Motivo:
el código actual busca pesos en la tabla legacy `sub_motivos` y luego
reescribe `detalles_evaluacion` y `evaluaciones`.

Eso mezcla el peso actual con evaluaciones históricas y puede alterar
trazabilidad. Se analizará en una fase específica antes de tocarlo.

### Validación segura

Primero consultar integridad de la versión activa:

```javascript
const token = localStorage.getItem('meca_token');

fetch('/api/matriz/versiones/4/integridad', {
  headers: { Authorization: `Bearer ${token}` }
}).then(async r => console.log(r.status, await r.json()));
```

Debe devolver `ok: true` para una matriz íntegra.

### Snapshot

Desde Supervisor se puede crear un snapshot nuevo. Debe quedar INACTIVO y
conservar la misma cantidad de frentes/atributos/submotivos/reglas.

No es necesario activarlo para validar la creación.
