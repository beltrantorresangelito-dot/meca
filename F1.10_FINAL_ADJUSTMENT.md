# F1.10 — Ajuste final del resolver

## Problema

Después de 0007, el resolver ya devuelve correctamente los tipos.

Pero existía un caso ambiguo:

- campaña tiene matriz vigente;
- no existe ninguna `versiones_matriz.fecha_vigencia <= fecha_consultada`;
- la función devolvía 0 filas.

## Solución

0008 hace explícito el contrato:

### Caso válido

Devuelve exactamente una fila con:

- Quiebre
- Campaña
- Matriz
- Versión

### Sin matriz vigente

Lanza excepción.

### Más de una matriz vigente

Lanza excepción.

### Matriz vigente sin versión aplicable

Lanza excepción:

`Existe matriz vigente ... pero no existe una versión de matriz aplicable.`

## Aplicar

```powershell
npm test
npm run db:status
npm run db:migrate
npm run db:status
```

## Pruebas

Actual:

```sql
SELECT *
FROM resolver_contexto_evaluacion(1, CURRENT_DATE);
```

Debe devolver 1 fila.

Histórica anterior a la primera versión:

```sql
SELECT *
FROM resolver_contexto_evaluacion(1, DATE '2025-01-01');
```

Debe devolver una excepción descriptiva, no 0 filas y no error de tipos.

## Criterio de cierre de F1.10

- 0 fail;
- 0008 aplicada;
- fecha actual devuelve 1 fila;
- fecha sin versión devuelve excepción de dominio clara;
- rollback/reaplicación funciona;
- MECA continúa operativa.
